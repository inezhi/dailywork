## 教学要求

- 学生水平，没有 DDD 背景；先讲人话，再给术语。
- 固定顺序：战略设计 → 战术设计 → 应用层 → 契约 → 实现。
- 一次一课、一次一个案例；检查题答完再继续。
- 案例只使用外部公开资料；禁止使用 `old/` 的 v1 代码。
- 案例要讲清背景、具体场景、后果，再讲概念。
- 未明确说“开始写代码”前，不写代码。
- 技术、极简，不要营销文案。
- 每课最后一个内容章节必须是本课总结（3–5 条），并列出 3–5 个关键词，放在检查题/产出之后。
- 关键词必须是概念或术语，不能用方法名、字段名、案例例子；技术名只有在它就是本章主题时才用。

## 课程组织

- 课程正文放在 `docs/ddd-course/`，每章一个 Markdown，本文件做索引。
- 每章固定结构：现实问题/踩坑 → 解决方式 → 概念 → 理论 → 检查题/闭环 → 本课总结 + 关键词。
- 未开讲的章节只放占位，不提前写正文。
- 课程表和当前进度只放在本文件，不单独维护重复的计划文件。
- `domain-model.html` 是聚合卡页面。
