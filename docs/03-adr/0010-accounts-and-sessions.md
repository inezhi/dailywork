# ADR-0010：账户、会话与每账户独立数据

状态：已接受 · 2026-10-27

## 背景

产品需要注册、登录、修改密码与头像，并计划在后续版本接入联网服务。当前业务数据为 SQLite 单库；如果直接给每张表加 `user_id`，查询和迁移成本高，也容易遗漏过滤条件。

## 决策

- 账户数据独立为 `<dataDir>/accounts.sqlite`：
  - `users`：用户名（大小写不敏感唯一）、scrypt 密码哈希与 salt、头像 BLOB 与 MIME。
  - `sessions`：32 字节随机 token、30 天过期、HttpOnly cookie。
- 每个账户使用独立的业务数据库 `<dataDir>/users/<userId>/data.sqlite`；首个账户注册时把根 `data.sqlite` 复制过去，后续账户创建全新欢迎工作区。
- HTTP 中间件按 `daily_session` cookie 选择账户数据库；CLI/MCP 使用 runtime Bearer token 映射首个账户；局域网配对创建首个账户的会话。
- 默认头像不落库：前端用用户名首字母 + 强调色生成；上传头像存 BLOB（≤5MB，PNG/JPEG/WebP/GIF）。
- 备份导出只包含当前账户数据库；导入暂存到该账户目录，重启后原子替换。账户备份不包含全局密钥文件，恢复后需重新填写 AI Key。
- 修改密码校验当前密码并删除该账户其他会话。

## 结果

- 账户隔离由文件边界保证，查询无需到处追加 `user_id`；删除/归档一个账户只需处理其目录。
- 后续接入联网服务时，可替换会话传输与服务托管方式，保留账户与数据模型。
- 代价：跨账户统计/共享需要显式聚合；账户目录需要备份策略覆盖。
