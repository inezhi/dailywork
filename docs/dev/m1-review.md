## 发现的问题

**「今日完成」按 UTC 日期分组，跨时区会错。**

- 现象：北京时间 00:03 完成的任务，今天页（`date=2026-11-27`）的「今日完成」里没有
- 根因：`completed_at` 是 UTC 时间戳，`date` 是客户端本地日期，服务端不知道客户端时区
- 影响：东八区用户在 00:00–08:00 完成的任务会落到前一天

**修复**：`GET /today` 增加可选 `tz`（IANA 名称，缺省 UTC）：

- 按客户端时区算出当天的 UTC 区间，`completed_at` 用区间判断，不比较日期
- 用 `AddDate(0, 0, 1)` 算次日零点，夏令时也正确
- 非法时区返回 400
- 日期列（`scheduled_date`、`due_date`）不受影响，仍按 `date` 比较

验证：同一任务在北京时间 00:09 完成，传 `tz=Asia/Shanghai` 出现在「今日完成」，不传（UTC）不出现。

## 复盘

- **发生了什么**：验收时发现完成时间跨 UTC 日期边界时分组错误
- **根因**：实现时把「客户端日期」直接与 UTC 时间戳比较，忽略了时区
- **下一步**：通知、统计等按天功能接入时，统一使用客户端时区换算出的区间
- **如何验证**：新增「东八区 00:30 完成」的边界测试；演示脚本固定覆盖跨日场景
